# httpSMS 家庭收信部署

把自有 SIM 收到的新短信，从专用 Android 手机上传到家庭电脑，在本机网页查看。默认仅收信；遵循用户指定的磁盘、网络范围和设备。此 Skill 提供工作流程，不包含完整修改版源码。

## 工作顺序

1. 检查实际工作区、已有部署和用户授权，定位 `android`、`api`、`web`、`compose.local.yml`、`deploy/local`。上游仓库为 https://github.com/NdoleStudio/httpsms 。本文引用的本地脚本属于加固修改版；若不存在，先实现或取得对应修改，不得声称克隆上游即可执行。
2. 新部署读取 [部署流程](references/deployment.md)；排障读取 [故障诊断](references/troubleshooting.md)；签名、升级和验收读取 [验收流程](references/acceptance.md)。按当前源码核实工具版本。
3. 查询本机真实网卡、手机连接和现有配置。历史对话中的 IP、号码、设备序列号、Firebase 项目和证书不能作为新部署默认值。
4. 先实现和验证，再交付操作说明及脱敏报告。将构建成功、手动启动成功和真实重启后自动恢复成功分开记录。

## 必须保留的设计约束

- 网页与通用 API 绑定电脑回环地址；手机入口仅绑定家庭网卡，限制接口、网络范围并校验用户 API 密钥。数据库和 Redis 不映射宿主机端口。
- Web、Android 与后端使用同一个自有 Firebase 项目。Web 配置和 Android `google-services.json` 是客户端配置；服务账号私钥只在后端保存。手机使用用户密钥，不使用系统管理密钥。
- HTTPS 验证证书链与主机名。手机仅对指定家庭地址信任用户 CA；不全局信任用户 CA、不以跳过 TLS 校验作为修复。电脑安装公开根证书，绝不向手机传入 CA 私钥。
- Docker 可能改写请求源地址。先用 Windows 防火墙限定家庭子网，再依据实际观察配置代理信任范围；不能盲目放行全部来源。
- Android 使用 WorkManager 持久化上传；每条短信保持稳定 UUID，仅收到合法成功响应后结束任务。失败退避重试，账号或服务器变化时阻止旧任务上传给新账号。后端按用户与 UUID 去重，消息和持久化事件队列事务提交。
- 仅接收新短信，不主动读取历史短信。检查最终合并 Manifest 不含 `SEND_SMS`、`READ_SMS`；后端封禁发送、发送计划及外部集成接口。权限和服务端限制都必须验证。
- 清除外部日志、分析、追踪和营销集成；Firebase Authentication 与 FCM 仍是外部依赖。默认数据库短信为明文，不能宣称完全离线或默认端到端加密。

## 权限与隐私

不要在输出、日志、Skill 或公开教程中记录真实号码、序列号、密钥、令牌、服务账号、短信正文或用户目录。凭据保持本地、限制 ACL 并排除 Git。报告仅记录状态、计数、版本和经过脱敏的故障。

实际发送短信、读取历史记录、清空数据、卸载应用、删除数据卷和重启设备按用户明确授权执行；有现成授权时不重复询问。电脑重启前确保用户已保存工作。离线测试设置网络恢复兜底。

## 交付要求

提供签名 APK、使用说明和验收记录；说明真实 SIM、Google 服务连接、家庭 Wi-Fi、电脑开机登录及手机重启后首次解锁等条件。说明没有自动短信过期清理，卸载或清除应用数据会影响队列，删除数据库卷会丢失消息。新部署不得继承其他人的签名私钥、账号或数据。
