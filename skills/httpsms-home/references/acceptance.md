# 签名、升级与验收

## 正式 APK

正式构建须非 debuggable，递增 versionCode，并检查合并 Manifest 的最终权限。签名私钥、密码及 lineage 私下保存、备份且排除 Git；后续升级复用同一身份。

已有 debug 安装迁移正式签名时，先确认旧签名材料及设备支持，可用 APK Signature Scheme v3 rotation lineage 保留数据和合法签名权限继承。不能为解决冲突直接卸载。全新安装不需要继承他人的 debug 身份。

核实实际脚本与设备后，示例：

```powershell
.\deploy\local\Build-Release.ps1 -VersionCode 2
adb -s DEVICE_SERIAL install -r PATH_TO_RELEASE_APK
.\deploy\local\Enable-LoginRecovery.ps1
```

示例参数必须替换。签名迁移需验证真实安装成功及原配置保留，不能只验证 APK 文件签名。

## 功能验收

使用用户自有号码，由用户发送普通测试短信；不得索要银行验证码。用不同标记统计，不在报告保存私人正文或号码。

| 测试 | 合格证据 |
|---|---|
| 正常收信 | 本机网页显示，数据库计数增加一条 |
| 手机锁屏、Wi-Fi 离线 | 离线时后端无新记录；恢复网络且不打开应用后补传一次 |
| 手机真实重启 | boot ID 变化；首次解锁后不打开应用，新测试短信收到一次 |
| 电脑真实重启 | OS 启动时间变化；登录任务自行执行、退出成功，HTTPS 可用、旧消息保留 |
| 入口限制 | 未认证请求被拒，非家庭来源被阻断，数据库与内部服务无公开端口 |

网络中断测试设置自动恢复兜底。电脑重启前备份数据库并确认用户已保存工作。失败修复后重新真实验证；不能用手动启动结果替代自动恢复。

按修改范围运行 Android 上传策略与 Go 去重/队列测试。破坏性数据库集成测试只针对独立测试库。事件重试通常为至少一次投递，不能推导所有外部副作用恰好一次。

## 报告与限制

记录构建版本、检查结果、脱敏计数、测试时间与自动/手动触发来源。只报告实际验证的场景，不承诺所有 Android 机型或所有验证码永不丢。

说明默认数据库明文、未实现自动过期清理、仍依赖 Google 服务；手机重启后首次解锁，电脑开机登录且避免休眠。卸载、强行停止、清除应用数据或删除数据卷会影响收信与队列。公开交付不得携带自己的数据、私钥或凭据。
